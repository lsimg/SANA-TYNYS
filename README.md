# SanaTynys

**SanaTynys** — веб-проект для осознанного наблюдения за никотиновой привычкой и поддержки при отказе от сигарет и вейпа. Он объединяет первоначальную настройку, расчёт прогресса, дневник состояний, календарь, короткие упражнения, информационную карту здоровья и ИИ-собеседника **Sana Coach**.

Проект ориентирован на русскоязычный интерфейс и казахстанский контекст: денежные показатели отображаются в тенге. Основная идея — помогать замечать триггеры и выбирать небольшой следующий шаг без стыда и давления.

Документ описывает фактическое содержимое папки. Здесь находится клиентский прототип: серверная часть, регистрация, база данных и система сборки отсутствуют. Медицинские тексты и ответы ИИ являются содержимым приложения; эта документация не подтверждает их клиническую точность.

## Две реализации в одной папке

В проекте существуют две самостоятельные реализации интерфейса. Из истории файлов нельзя установить, какая из них появилась раньше.

| Характеристика | Многостраничная реализация | Одностраничная реализация |
| --- | --- | --- |
| Входная страница | `index.html` | `sanatynys.html` |
| Навигация | Переходы между отдельными страницами | Переходы к разделам внутри страницы |
| Стили и логика | Общие `styles.css`, `app.js` и встроенные сценарии страниц | Собственные встроенные стили и сценарий |
| Первоначальная настройка | Отдельная анкета из пяти шагов | Форма настроек в разделе прогресса |
| ИИ-провайдер | Groq | Google Gemini |
| Упражнения | Отдельная страница с десятью упражнениями | Отдельного каталога упражнений внутри страницы нет |
| Карта здоровья | Подробная страница с вкладками | Более короткая карта этапов |
| Хранилище | Ключи с префиксом `sana` | Собственные ключи без этого префикса |

Для знакомства с многостраничным интерфейсом открывайте `index.html`. Страница `sanatynys.html` доступна по своему адресу и не подключает общие `app.js` и `styles.css`. Изменения этих двух файлов не обновляют её встроенный код.

История и настройки между реализациями автоматически не переносятся, даже если обе открыты на одном адресе сервера.

## Технологии и зависимости

- **HTML5** — разметка и отдельные страницы.
- **CSS** — переменные оформления, сетки, адаптивные правила и анимации.
- **Обычный JavaScript** — обработка событий, расчёты, работа с документом и сетевые запросы. Фреймворки не используются.
- **`localStorage`** — сохранение данных в браузере в виде строк JSON.
- **`fetch`** — прямые обращения к внешним сервисам ИИ.
- **`Blob` и `URL.createObjectURL`** — создание скачиваемого дневника.
- **`IntersectionObserver`** — появление элементов при прокрутке.
- **Google Fonts** — загрузка шрифтов Instrument Serif и DM Sans.

Устанавливать зависимости через `npm` и собирать проект не требуется. Для работы нужен современный браузер с включённым JavaScript и разрешённым локальным хранилищем.

Интернет нужен для ИИ-запросов и загрузки внешних шрифтов. Для локальных расчётов и упражнений обращения к ИИ не требуются. Автономная установка приложения и кэширование через служебный сценарий не реализованы.

## Локальный запуск

### Через Python в Windows

Откройте PowerShell в папке проекта и выполните:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Если команда `python` недоступна, но установлен запускатель Python:

```powershell
py -m http.server 8000 --bind 127.0.0.1
```

Откройте в браузере:

- [Главную страницу](http://127.0.0.1:8000/index.html).
- [Первоначальную настройку](http://127.0.0.1:8000/onboarding.html).
- [Одностраничный вариант](http://127.0.0.1:8000/sanatynys.html).

Остановить сервер можно сочетанием `Ctrl+C` в его окне. Если порт занят, укажите другой номер и замените его в адресе браузера.

Python используется только как простой сервер статических файлов. Он не выполняет код приложения и не скрывает ключи ИИ.

### Через редактор кода

Можно использовать локальный сервер статических файлов из редактора: открыть папку, запустить сервер и перейти к `index.html`. Встроенной команды запуска в проекте нет.

Открытие HTML двойным щелчком может показать интерфейс, однако для предсказуемой работы хранилища и сетевых запросов используйте HTTP-сервер. При адресах `file://` поведение зависит от браузера.

## Пользовательский сценарий

1. Открыть главную страницу и нажать «Начать мой путь».
2. Выбрать тип привычки, триггеры, характер поведения и подходящий режим.
3. Указать дату начала и исходные расходы.
4. После завершения анкеты перейти на страницу «Мой путь».
5. Отмечать состояние, фиксировать сегодняшний день в календаре и пользоваться упражнениями.
6. При необходимости открыть Sana Coach: чат использует сохранённые сведения как контекст.
7. Скачать дневник или очистить данные через предусмотренные элементы интерфейса.

Страницы можно открывать напрямую. Проверки входа и обязательного прохождения анкеты нет: признак её завершения сохраняется, но доступ к разделам не ограничивает.

## Возможности страниц

### Главная — `index.html`

Содержит описание проекта, принципов работы, основных возможностей и ссылки на разделы. Внизу доступны экспорт дневника и очистка данных. Часть информационных ссылок, например «Контакты» и «Конфиденциальность», имеет адрес `#` и пока не ведёт к отдельным материалам.

Числа в демонстрационных блоках главной страницы заданы в разметке. Они не являются персональными показателями пользователя.

### Первоначальная настройка — `onboarding.html`

Анкета состоит из пяти шагов:

1. **Тип привычки:** сигареты, вейп, оба варианта или наблюдение за привычкой.
2. **Триггеры:** несколько вариантов, включая стресс, скуку, компанию, кофе, тревогу и привычный маршрут.
3. **Характер поведения:** автоматическое, эмоциональное, социальное курение, курение при усталости либо неопределённый вариант.
4. **Режим:** бросить сразу, снижать постепенно или наблюдать семь дней.
5. **Расчёт:** дата начала, сигареты в день, стоимость и размер пачки, недельные расходы на вейп, число эпизодов вейпа в день.

Кнопка пропуска также сохраняет настройки и открывает личную панель. Если тип привычки не выбран, используется режим наблюдения `observe`.

Выбранный режим сохраняется в профиле и передаётся в контекст ИИ. Отдельного алгоритма постепенного снижения или семидневной программы в коде нет.

### Личная панель — `dashboard.html`

Показывает количество дней от указанной даты, приблизительную экономию, расчётное число неиспользованных сигарет или эпизодов вейпа и текущий этап карты тела.

Дополнительно содержит:

- Кнопки отметки состояния: спокойно, тянет курить, был срыв, хочется выговориться.
- Короткую подсказку после отметки состояния.
- Мини-календарь последних 14 дней.
- Ссылки на чат, упражнения, календарь и карту здоровья.

Отметка состояния сохраняется отдельно от календаря. Нажатие «Был срыв» на этой странице само по себе не создаёт календарную запись и не изменяет дату начала.

### Календарь — `calendar.html`

Отображает последние 30 дней и позволяет сохранить один статус за текущую дату:

| Значение в данных | Подпись в интерфейсе |
| --- | --- |
| `smoke_free` | Без никотина |
| `craving` | Тяга |
| `relapse` | Срыв |
| `skipped` | Пауза |

Заметка сохраняется при нажатии кнопки статуса. Повторное нажатие обновляет запись за сегодня. Пустая новая заметка сохраняет предыдущий текст, поэтому удалить старую заметку таким способом нельзя.

Дни без записи визуально тоже показываются как «Пауза». Интерфейса редактирования прошлых дат нет.

### Упражнения — `exercises.html`

Каталог формируется JavaScript и открывает упражнения в модальном окне.

| Упражнение | Что реализовано |
| --- | --- |
| Дыхательный пузырь | Четыре цикла: вдох 4 секунды, задержка 7, выдох 8; запуск, пауза и завершение |
| 90 секунд тяги | Обратный отсчёт и выбор субъективного результата |
| Назови триггер | Выбор триггера, запись в историю триггеров и упражнений |
| Руки заняты | Таймер на 120 секунд и выбор действия |
| Холодная вода | Инструкция и отметка результата |
| Заземление 5–4–3–2–1 | Поля для наблюдений о предметах, звуках, ощущениях, запахах и фразе поддержки |
| Письмо тяге | Два текстовых поля и кнопка сохранения факта выполнения |
| Сценарий отказа | Выбор фразы для социальной ситуации |
| Мини-прогулка | Таймер на 180 секунд и поле оценки тяги |
| Разбор срыва без стыда | Сохранение места, окружения, эмоции и следующего действия; ссылка на чат |

Факт завершения и некоторые выбранные результаты сохраняются. Тексты заземления, письма тяге и оценка после прогулки сейчас не включаются в сохраняемый результат. Подробный разбор срыва сохраняется в отдельную историю.

### Здоровье — `health.html`

Содержит четыре вкладки:

- «Во время курения» — информационные карточки и схема цикла привычки.
- «Первые 72 часа» — ранние этапы.
- «Недели и месяцы» — этапы от недели до девяти месяцев.
- «Долгий срок» — этапы от одного года до пятнадцати лет.

Общий массив `BODY_STAGES` содержит 19 этапов, включая начальный. Карточки описывают изменения, возможные ощущения и поддерживающую фразу. Также есть восемь раскрывающихся карточек симптомов и ссылки на упражнения.

Текущий этап определяется только по дате начала. Приложение не получает измерения здоровья, не диагностирует состояние и не проверяет, действительно ли пользователь воздерживался от никотина.

### Чат — `coach.html`

Поддерживает ввод текста, быстрые сообщения, восстановление истории, индикатор ожидания, очистку переписки и экспорт дневника. `Enter` отправляет сообщение, `Shift+Enter` добавляет перенос строки.

История хранится с ролями `user` и `model`. Перед отправкой в Groq роль `model` преобразуется в `assistant`. Ответ сначала экранируется как текст; из разметки поддерживается только выделение `**жирным**`.

### Самостоятельная страница — `sanatynys.html`

Объединяет рекламные блоки, форму настроек, панель прогресса, отметки состояния, календарь за 30 дней, короткую карту тела, пример анализа триггеров, чат и раскрывающиеся вопросы.

Её особенности:

- Настройки меняются непосредственно в разделе прогресса.
- Отметка состояния одновременно инициирует сообщение в Gemini.
- Триггеры извлекаются из текста по простым ключевым словам.
- Проценты в блоке «Твои топ-триггеры» заданы вручную как пример профиля; из истории они не рассчитываются.
- ИИ-контекст включает количество календарных срывов за последние семь дней.
- Есть экспорт дневника и очистка истории чата. Кнопки общей очистки всех данных этой реализации нет.

Упоминания тарифов, консультаций специалистов, регистрации и мобильных приложений в её текстах не подтверждаются реализацией этих функций в папке.

## Расчёт показателей

### Начальные настройки

| Параметр | Поле | Значение по умолчанию |
| --- | --- | --- |
| Дата начала | `startDate` | Пустая строка до сохранения настроек |
| Тип привычки | `habitType` | `cigarettes` |
| Сигарет в день | `cigarettesPerDay` | 10 |
| Стоимость пачки | `packPrice` | 900 ₸ |
| Сигарет в пачке | `cigarettesPerPack` | 20 |
| Расходы на вейп за неделю | `vapeWeeklyCost` | 3000 ₸ |
| Эпизодов вейпа в день | `vapeEpisodesPerDay` | 8 |

При сохранении анкеты многостраничной версии пустая дата заменяется текущей. Некоторые начальные даты в формах берутся через `toISOString()`, то есть по всемирному времени, а календарь использует местную дату браузера.

### Формулы

Количество дней — целая часть разницы между текущим временем и полуночью выбранной даты, делённой на 86 400 000 миллисекунд. Отрицательный результат ограничивается нулём. Без даты либо при некорректной дате получается ноль.

```text
Экономия на сигаретах = дни × сигареты в день × цена пачки / сигареты в пачке
Экономия на вейпе = дни / 7 × расходы на вейп за неделю
Неиспользованные сигареты = дни × сигареты в день
Неиспользованные эпизоды вейпа = дни × эпизоды в день
```

Для сигарет и вейпа используются соответствующие показатели. В смешанном режиме они складываются. В режиме наблюдения `observe` многостраничная версия выбирает большее из двух значений экономии и большее из двух значений количества. В одностраничной версии аналогичная ветка предусмотрена для `not sure` и `not_sure`.

Деньги и количество округляются до целого. Например, за 14 дней при 10 сигаретах в день, пачке из 20 сигарет и цене 900 ₸ расчёт даст 6300 ₸ и 140 сигарет.

Это оценка по исходной привычке. Статусы календаря и срывы не вычитаются из суммы и не обнуляют счётчик. Поэтому показатель дней не является проверенной непрерывной серией без никотина.

## Архитектура кода

В многостраничной версии каждая страница подключает `styles.css` и `app.js`. Её собственные действия описаны во встроенном сценарии после подключения общего файла.

`app.js` предоставляет общий объект `window.SanaApp`:

| Группа | Основные элементы |
| --- | --- |
| Константы | `SANA_KEYS`, `BODY_STAGES`; внутри файла также находятся `DEFAULT_SETTINGS` и настройки Groq |
| Чтение и запись | `getStorage`, `setStorage`, `getQuitSettings` |
| Расчёты | `getDaysWithoutSmoking`, `calculateProgress`, `getBodyStage` |
| Дневниковые действия | `saveCheckin`, `saveCalendarEntry`, `recordTrigger`, `saveExerciseResult` |
| Отображение | `renderProgressCards`, `renderMiniCalendar`, `statusLabel`, `formatCoachMessage` |
| ИИ | `buildCoachContext`, `callSanaCoachAPI` |
| Управление данными | `downloadJournal`, `clearAllData` |

При событии `DOMContentLoaded` общий файл настраивает навигацию, анимации появления и обработчики кнопок экспорта и общей очистки. Отдельного маршрутизатора нет: навигация между страницами выполняется обычными ссылками.

В `sanatynys.html` похожие функции определены отдельно. Общего модуля между двумя реализациями нет.

| `sanaCheckins` | Отметки состояния с временем | Последние 160 записей |
| `sanaTriggerHistory` | Триггер, источник и время | Последние 120 записей |
| `sanaExerciseHistory` | Тип упражнения, результат и время | Последние 160 записей |
| `sanaRelapseReviews` | Подробные разборы срывов | Последние 80 записей |

Ограничения относятся к сохранённому хранилищу; например, массив переписки в памяти открытой страницы может быть длиннее.

### Хранилище одностраничной версии

Используются ключи `chatHistory`, `userProfile`, `quitSettings`, `quitCalendar`, `checkins`, `triggerHistory`. При записи сохраняются последние 80 сообщений, 120 отметок состояния и 80 записей триггеров. Календарь хранится объектом по датам.

### Где находятся данные

Данные сохраняются в профиле браузера и привязаны к сочетанию протокола, адреса и порта сайта. Поэтому `localhost:8000`, `127.0.0.1:8000` и тот же сайт на другом порту имеют разные хранилища. Между устройствами и браузерами синхронизации нет.

Собственное шифрование данных приложение не выполняет. При отправке в ИИ часть пользовательских сведений уходит внешнему провайдеру. Соответственно, утверждения одностраничного раздела вопросов о шифровании и отсутствии передачи третьим лицам не соответствуют фактическому поведению кода.

### Экспорт и удаление

Кнопка «Скачать мой дневник» создаёт файл `sanatynys-diary-ГГГГ-ММ-ДД.json` в формате JSON. Экспорт многостраничной версии включает профиль, настройки, чат, календарь, состояния, триггеры, упражнения и разборы срывов. Признак прохождения анкеты в экспорт не включён.

Одностраничная версия экспортирует собственный набор данных с другими названиями полей. Обратного импорта и восстановления из файла ни в одной реализации нет.

В многостраничном сайте общая очистка запрашивает подтверждение, удаляет девять ключей `SANA_KEYS` и перезагружает страницу. Она не удаляет ключи одностраничного варианта. Очистка чата удаляет только его историю.

## Подключение Sana Coach

### Groq в многостраничном сайте

Настройки находятся в `app.js`:

- `GROQ_API_KEY` — ключ доступа.
- `GROQ_MODEL` — основная модель; в коде указана `llama-3.3-70b-versatile`.
- `GROQ_FALLBACK_MODELS` — резервные модели; указана `llama-3.1-8b-instant`.
- `SANA_COACH_SYSTEM_PROMPT` — инструкции о роли, языке и стиле помощника.

Браузер отправляет запрос `POST` на `https://api.groq.com/openai/v1/chat/completions` с заголовком авторизации. В запрос входят системная инструкция, пользовательский контекст и последние 14 сообщений. Параметры генерации в коде: `temperature: 0.7`, `max_completion_tokens: 900`.

Контекст включает весь сохранённый профиль и настройки, расчётный прогресс, последние три состояния, семь календарных записей, шесть записей триггеров и четыре типа последних упражнений. Подробные разборы срывов в этот контекст не включаются. Указанные в контексте «частые триггеры» фактически являются последними записями, без подсчёта частоты.

Код перебирает модели, а при некоторых сообщениях о перегрузке и лимитах выполняет повторную попытку после 900 миллисекунд. При неудаче возвращает заранее заданный текст о проблеме подключения. Срок ожидания запроса и потоковая выдача ответа не настроены.

### Gemini в одностраничном сайте

Настройки находятся внутри `sanatynys.html`: `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_FALLBACK_MODELS` и собственная системная инструкция.

В коде основной моделью указана `gemini-2.5-flash`, резервными — `gemini-2.0-flash` и `gemini-2.0-flash-lite`. Запросы отправляются на `https://generativelanguage.googleapis.com/v1beta/models/…:generateContent` с заголовком `x-goog-api-key`.

В запрос включаются контекст и последние 12 сообщений. Указаны `temperature: 0.7` и `maxOutputTokens: 1400`. При признаках незаконченного ответа предусмотрено до двух запросов продолжения. Доступность перечисленных моделей зависит от сервиса и учётной записи; сами их названия здесь приведены из исходников.

### Ключи доступа

Перед загрузкой на GitHub встроенные ключи заменены на заглушки `PASTE_YOUR_GROQ_API_KEY_HERE` и `PASTE_YOUR_GEMINI_API_KEY_HERE`. Без настройки доступа чат не обращается к провайдеру и сообщает об отсутствующем ключе; остальные разделы работают независимо от ИИ.

Прежние значения сохранены только локально в `.local-api-keys.json`, исключённом из Git через `.gitignore`. Этот файл не входит в репозиторий, не загружается приложением и не должен попадать на публичный сервер. Работоспособность ключей не проверялась.

Ключ в клиентском JavaScript доступен посетителю сайта через исходный код и инструменты браузера. Простое добавление файла `.env` к этому статическому проекту не скроет ключ и не подключит его автоматически: механизма загрузки переменных окружения здесь нет.

Для публичного использования подключения необходимо перенести обращения к провайдерам на серверный обработчик. Если прежние ключи ранее публиковались, их следует отозвать. Новые ключи должны храниться в окружении сервера. В `app.js` уже есть комментарий о таком переносе, но сам серверный обработчик отсутствует.

## Оформление и адаптивность

Общий файл `styles.css` задаёт тёмно-синие, мятные и кремовые цвета, скруглённые карточки, фиксированную навигацию, сетки, модальные окна и оформление чата.

- Instrument Serif применяется к крупным заголовкам и числам.
- DM Sans используется для основного интерфейса.
- На ширине до 1024 пикселей сетки упрощаются, часть блоков переходит в две колонки.
- На ширине до 768 пикселей основные сетки становятся одноколоночными, а навигация многостраничного сайта открывается кнопкой «Меню».
- Анимируются дыхательный круг, волна тяги, индикатор прогулки и появление карточек при прокрутке.

Одностраничный вариант имеет собственные правила оформления и адаптивности. Его изменения выполняются внутри блока `<style>` в `sanatynys.html`.

## Ограничения текущей реализации

Следующие особенности видны в исходниках и важны при использовании и доработке:

1. **Нет серверной инфраструктуры.** Отсутствуют учётные записи, синхронизация, защищённое хранение ключей и централизованное управление данными.
2. **Расчёты не учитывают фактическое потребление.** Они зависят от даты и исходных расходов, даже при отмеченных срывах или режиме наблюдения.
3. **Точность времени ограничена целыми днями.** Карта содержит часовые этапы, но получает округлённое число дней. Поэтому этапы 20 минут, 8 часов и 12 часов не становятся текущим этапом автоматически в первые сутки.
4. **Таймеры упражнений не очищаются при закрытии окна.** Они могут продолжать работать и сохранять завершение после закрытия; открытие другого упражнения может привести к обращению старого таймера к уже заменённым элементам.
5. **Часть полей упражнений не сохраняется.** Сообщение об успешном сохранении может относиться только к факту выполнения. Выбор «Свой ответ» в сценарии отказа также не открывает отдельное поле ввода.
6. **Несколько завершений могут создать несколько записей.** Ручное завершение и автоматическое окончание таймера не объединены в одну операцию.
7. **Параллельные сообщения не полностью заблокированы.** В многостраничном чате отключается кнопка отправки, но быстрые кнопки и обработчик `Enter` не проверяют общий признак ожидания.
8. **Обработка хранилища частичная.** Ошибка чтения JSON перехватывается, но соответствие структуры данных ожидаемому формату и ошибки записи отдельно не обрабатываются.
9. **Повторная анкета не заполняется полностью прежними значениями.** Ранее заданная дата подставляется, но варианты выбора и числовые поля не восстанавливают весь сохранённый профиль.
10. **Доступность интерфейса требует доработки.** Например, у модальных окон упражнений нет управления фокусом и обработчика закрытия по `Escape`.
11. **Часть интерфейса демонстрационная.** Информационные ссылки с `#`, рекламные числа и пример процентов триггеров не являются готовыми сервисами или персональной аналитикой.
12. **Тексты о здоровье не привязаны к проверенным источникам внутри проекта.** При этом оба типа привычки используют общую карту этапов; отдельной модели восстановления после вейпа нет.

### Ручная проверка

Автоматический набор тестов в папке отсутствует. Для проверки изменений можно пройти следующие сценарии:

1. Запустить локальный сервер и проверить переходы между страницами.
2. Завершить анкету; обновить личную панель и убедиться, что настройки сохранились.
3. Проверить расчёт на известных исходных данных, например на примере за 14 дней выше.
4. Сохранить состояние и календарную отметку с заметкой; обновить страницу и проверить сохранение.
5. Открыть упражнения, проверить выбор триггера, таймеры и сохранение разбора срыва.
6. Переключить вкладки здоровья и раскрыть карточки симптомов.
7. Проверить чат с настроенным подключением, историю, перенос строки и сообщение при сетевой ошибке. Такие запросы передают контекст внешнему сервису и используют его лимиты.
8. Скачать дневник и проверить содержимое JSON.
9. Проверить очистку данных в отдельном профиле браузера либо после экспорта нужных записей.
10. Проверить узкую ширину окна и меню; посмотреть ошибки в инструментах разработчика.
11. При изменении `sanatynys.html` повторить проверки отдельно: её логика и хранилище самостоятельны.

Это сценарии для дальнейшей проверки, а не утверждение о проведённом тестировании интерфейса или внешних ИИ-сервисов.

## Размещение сайта

Клиентские файлы можно обслуживать обычным сервером статического содержимого. Для многостраничного сайта нужны HTML-файлы, `app.js`, `styles.css` и папка `assets`. Главным документом должен быть `index.html`. Для отдельной страницы `sanatynys.html` нужны сама страница и используемый ею логотип; шрифты загружаются извне.

Конфигурации конкретного хостинга в папке нет. Для публикации с работающим ИИ требуется сначала решить вопрос серверного хранения ключей, описанный выше. Не добавляйте действующие ключи в клиентские файлы и не копируйте локальный файл `.local-api-keys.json` на сервер.

Внешних серверных маршрутов для обычной навигации не требуется: каждая страница имеет собственный HTML-файл. Адрес и порт опубликованного сайта создадут новое браузерное хранилище, поэтому локальная история автоматически на него не перенесётся.

Отдельного файла лицензии и условий использования в папке нет.
